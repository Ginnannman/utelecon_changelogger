# utelecon-changelog

[utelecon](https://utelecon.adm.u-tokyo.ac.jp/) の公開ページについて、2時点の間に変わったページの URL と差分を記録します。

ソースの差分ではなく、[utelecon/utelecon.github.io](https://github.com/utelecon/utelecon.github.io) の2時点をそれぞれビルドした結果を比較します。そのため、ナビゲーション・レイアウト・部品の変更によって出力が変わったページも検出できます。

記録は [reports/](reports/README.md) にたまります。

## 使い方

### 定期実行

毎週月曜 03:00（JST）に自動で実行します。前回の終了時点から実行時点までを比較し、`reports/` と `state/last.json` をコミットします。初回は直近7日間を対象にします。

### 手動実行

Actions タブ →「utelecon changelog」→「Run workflow」で、次の2項目を入力します。

- 開始: `2026-09-01 00:00` の形式（JST）
- 終了: 同じ形式。空欄にすると実行時点

手動実行の結果は、ディレクトリ名の末尾に `-manual` を付けて保存します。`state/last.json` は更新しないので、定期実行の続きには影響しません。同じ期間で再実行すると、その期間の記録を上書きします。

## 時点の決め方

時点 T の状態は、`master` の first-parent 履歴のうち、T 以前に入った最後のコミットです。PR のマージコミットではマージ時刻がコミット時刻になるので、「T までにマージされたもの」に相当します。

古い日付のコミットが後から直接 push された場合に T 以前と誤認しないよう、履歴を古い順にたどったときのコミット時刻の累積最大値で判定します。定期実行では、前回の比較先コミットを `state/last.json` から読み、今回の比較元にします。

各時点は、そのコミットの `.github/workflows/astro.yml` に書かれた Node のメジャー版でビルドします。書かれていなければ 22 を使います。

## 報告の構成

```
reports/
  README.md                          一覧（新しい順）
  2026/20260907-0300_20260914-0300/
    README.md                        期間の概要と各一覧
    changes.json                     機械可読の要約
    pages/<ページ>.md                 個別ページの差分（日本語と英語をまとめる）
    common/content-<n>.md            複数ページに共通する本文の変更
    common/chrome-<n>.md             共通部分（ヘッダ・フッタ等）の変更
```

変更は次のように分類します。

- **個別ページ**: 本文（`<main>`。目次は除く）とタイトル・説明文の差分。`/xxx/` と `/en/xxx/` を1行にまとめます。
- **複数ページに共通する本文の変更**: まったく同じ差分が5ページ以上に生じたもの。緊急のお知らせの表示や一括置換が該当します。
- **共通部分の変更**: `<main>` の外側（ヘッダ・フッタ等）の差分。差分が同じページを1件にまとめます。
- **スタイル・スクリプト**: `/_astro/` のファイル名（ハッシュ入り）の増減。
- **配布ファイル・静的ファイル**: HTML 以外のファイルの追加・削除・内容の変更（SHA-256 で比較）。
- **リダイレクト**: `meta refresh` を持つページの転送先の追加・削除・変更。

RSS（`rss.xml`）は対象外です。

差分は、HTML を「見出しは `#`、箇条は `-`、表は `| |`、リンクは `[文字](URL)`」の行に変換してから比較しています。見た目だけの変化（CSS による表示の変化など）は、ページ単位では検出しません。

## 構成

| ファイル | 役割 |
|---|---|
| `.github/workflows/changelog.yml` | 実行の流れ（時点の決定 → 2時点のビルドとスナップショット → 比較・記録） |
| `scripts/resolve.sh` | 期間から比較する2つのコミットを決める |
| `scripts/snapshot.mjs` | ビルド出力（`dist`）から比較用のスナップショットを作る |
| `scripts/lib/extract.mjs` | HTML を差分用の行に変換する |
| `scripts/compare.mjs` | 2つのスナップショットを比較し、報告を書く |
| `scripts/index.mjs` | `reports/README.md`（一覧）を作り直す |
| `test/run.mjs` | 模擬ビルド出力による試験（`npm test`） |

同じコミットのスナップショットは Actions のキャッシュに保存して再利用します。スナップショットの形式を変えた場合は、キャッシュキーの `snapshot-v1` を上げてください。

## 制約

- 古い時点ほど、その時点の依存関係ではビルドできなくなる可能性があります。ビルドに失敗した場合、記録は書かれず、`state/last.json` も進みません。
- 差分は公開 HTML に基づくので、ビルド時に生成される文言（自動生成の説明文など）の変化も差分に現れます。
